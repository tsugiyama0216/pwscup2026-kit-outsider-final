## 保存範囲

攻撃コード・テスト・説明書、全バージョンの候補CSV、公式フィードバックに加え、
`local-output/` の研究用 Python / Markdown / JSON / CSV を元のパスで保存する。
不採用・無効と判断した実験、shadowの参照ラベル、seedと入力hashも含める。
元のパスを保つことで、ベンチマークの相対パス参照を維持する。
アーカイブブランチの `.gitattributes` は改行の自動変換を止め、Windows/Linuxで
CSV・feedback・原稿のSHA-256が変わらないようにする。通常のテキスト差分表示は
無効にしない。既存Windows作業ファイルのCRLFも、そのまま保存する。

正解ラベル付きshadowは人工実験の真値であり、本番の隠し正解ではない。
公開challengeのQIや派生特徴が一部含まれるため、このアーカイブは非公開のまま
扱う。実データのB/B_self/A_bgはダウンロード先からコピーしていない。

## 除外と認証情報

- token.txt、提出用ZIP、Pythonキャッシュ、実行環境は新たな保存対象にしない。
- トークン入りZIPとトークン本体は手元に残す。削除しない。
- 実トークンが古いGit履歴に存在する件は所有者に説明済み。所有者は未失効と
  回答したうえで、既存の非公開履歴に残すことを明示的に了承した。
- 履歴削除・force pushは行わない。現在の追跡対象から実token.txtを外しても、
  過去履歴から除去したことにはならない。漏洩範囲を将来制限するには失効・
  再発行が必要であり、非公開であることだけでリスクがなくなるわけではない。
- `.gitignore` の `/local-output/` は維持する。今回の明示した研究ファイルだけを
  選択して追跡し、新規のZIPや一時ファイルが自動追加されないようにする。
- 既存スターターキットのサンプルZIP 2個は例外として維持する。圧縮されたままの
  バイト検査だけでなく、内部ファイルもメモリ上で認証情報検査を行う。

## 完全性の確認

`prelim-2026-manifest.json` に保存対象の元パス・サイズ・SHA-256と除外理由を記録。
manifest自身は自己参照を避けるためhash対象外。`archive_prelim_work.py` が選択と
監査を再現する。既知トークンとの完全一致と一般的な認証情報パターンを検査し、
検出時は内容を表示せず、アップロード対象の作成を止める。
ステージ後には `archive_prelim_work.py --verify-staged` でGitオブジェクトの内容と
manifestを再照合し、監査後に未検査の変更や改行変換が混入していないことを確認する。

この検査はあらゆる未知の秘密情報を検出できる保証ではない。リポジトリを
公開へ切り替えたり、第三者へミラーする前には別途データ・履歴監査を行う。
