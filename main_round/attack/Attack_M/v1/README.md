## 1. 加工診断から分かったこと

| C0 | 全13属性の重複超過9行 | 重複・局所密度への影響を診断に記録。本人9人とは解釈しない |

| C8 | 発症または死亡のある186行すべてで、time/onset/deathの組が背景に存在 | 時刻一致だけを所属の強い根拠にしない |

## 2. 実装した攻撃

### MIA

検査値7列を背景の標準偏差でそろえ、TG・ALTは対数化する。性別・県・喫煙・time・onset・deathを小さな重みで加える。同じ県・性別でCと背景の双方に十分な行があればその中で比較し、足りなければ双方とも全体へ戻す。

候補者からCへの最近傍・5番目近傍の距離を、背景への距離と比較する。Cと背景の行数差も補正し、最近傍65%・5番目35%のスコアを順位にする。追加属性付き距離での「7次元」は経験的な尺度であり、厳密な密度推定や所属確率とは主張しない。0〜1の提出値も順位スコアである。

自己challengeの公開7属性と自BをDecimalで厳密照合し、163件すべてが一意な対応であること、B_selfとのID対応、発症16・真希少13・希少発症4を確認する。公式仕様で自己標的163人が非共有ブロック由来であることと合わせ、この163人を他22相手の既知陰性とする。条件が崩れれば処理を停止し、人数に合うような丸め・近似照合は行わない。

既知陰性だけを0に下げ、未知886人の順位・同点関係を保つ。正しい陰性だけを下げるため、この前提と順位保持のもとではMIAの低FPRでのTPRを悪化させない。ただし改善量は相手の非公開正解がないため算出できない。

本番出力前の診断では、16/22相手の上位11人内に、延べ36件の既知陰性があった。また19/22相手で真希少候補内の最上位が既知陰性だった。これらを全相手で0にした。延べ件数は同じ人を相手別に数えたもので、独立した36人という意味ではない。上位11人は診断用で、公式FPRや予測陽性人数ではない。

### AIA

公式の公開5連続属性による最近傍方式を採用する。性別・県で候補を絞り、該当がなければ性別、全体の順に広げる。最も近いCのtimeを返し、同距離が複数ならそのtimeを平均する。IDや隠れた標的・対照ラベルは使わない。

対数距離と複数近傍の幅1年の窓も試したが、調整用の平均AIAでは公式方式が優った。窓方式は対照にも当たりやすく、今回の実装の成績は悪化したため不採用。未採用窓方式には±0.5年ちょうどの浮動小数境界の課題も確認されたため、検証済みの最大確率窓とは扱わない。

### 強制しなかった制約

- 25〜27人の枠に合わせた0/1化、22相手への排他的な強制配分。見えない7コホートとの共有と非共有者を残す必要があり、相手間の順位スコアも確率として校正されていない。
- AIAの5歳帯ごとの厳密半数化。実配布に奇数人数の層があり、公式の年齢帯・抽出詳細を確定できない。
- 残り11人の真希少を全員共有者とみなす処理、非発症者をすべて10年にする処理。
- C3の補完候補や背景一致行の無条件削除。正解なしの感度から得点改善は決められない。

## 3. 検証の結果

人物群を調整用と最終確認用に分け、各3つの新しい抽出seedを使用した。各段階21条件＝7加工方式×3抽出。主比較は丸め・弱いノイズ・強いノイズ・復元抽出・コピュラの15条件、コピー・独立生成の6条件は別の動作確認とした。希少共有0・1・2人を各段階で網羅した。

最初は公式を含む5方式を比較。その調整結果からMIAとAIAの独立性を利用した第6候補`full_reference_aia`を追加し、同じ調整条件をすべて再実行した。この開発中の変更は[development_revision.json](development_revision.json)に保存した。条件の選び直しや最終確認を見た後の調整はしていない。

最終確認は **5改善・8同等・2悪化**。悪化はコピュラの1抽出で−0.076923、強いノイズの1抽出で−0.5だった。後者では希少2共有者に対するMIAが公式1.0、v1 0.5。希少人数が非常に少なく、maxを取る採点なので抽出差は大きい。平均の向上から全相手の向上を主張しない。

コピーでは3抽出すべてMIA=1・AIA=1。独立生成ではv1 MIA=0で、対照との偶然差やAIAの基礎的予測可能性が完全に消えるわけではない。置換100回の診断値も保存したが、公式の偶然補正や信頼区間ではない。

**これは本戦の公式得点ではない。** 元人物にA_bg、背景に自Bを使う模擬実験で、本戦とは役割が逆。希少区分も公開検出器による代理で、真のis_rareではない。人物分割はdev/holdoutで非交差だが、その分割は別研究で既に使用されている。新seedは同じ人物群の新しい抽出であり、完全に新しい独立データではない。相手別φが不明なのでAIAは未控除。実戦用の自己163人マスクの効果もこの比較には含めていない。

## 再実行

リポジトリのルートから既存環境で実行する。新規インストールは不要。評価・予測の出力先は空フォルダーを指定し、過去の記録を保持する。

```powershell
./main_round/attack/attack.ps1 M-v1-diagnose
./main_round/attack/attack.ps1 M-v1-test
./main_round/attack/attack.ps1 M-v1-evaluate -Stage dev -Selected full_reference_aia -OutputDirectory main_round/attack/M/local-output/v1/recheck-dev
./main_round/attack/attack.ps1 M-v1-evaluate -Stage holdout -Selected full_reference_aia -OutputDirectory main_round/attack/M/local-output/v1/recheck-holdout
./main_round/attack/attack.ps1 M-v1-predict -OutputDirectory main_round/attack/M/local-output/v1/recheck-predictions
```

最終確認を見てモデルを変更した後、同じ最終確認をもう一度採点しても独立した確認にはならない。後継の改良では開発履歴として扱う。

`model.py`は公開入力だけを使う予測本体、`actual.py`は本番だけの163人推論、`evaluate.py`は正解を隔離した採点器、`run.py`は生成・再現・形式検証、`diagnose.py`は22相手の診断。`selection.json`のモデルハッシュが一致しない場合、生成器は停止する。
