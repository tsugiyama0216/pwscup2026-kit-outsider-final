# 本戦攻撃 v1 の作戦と根拠

**実装後の追記（2026年9月30日）：** この文書は作戦検討時点の記録。後続の[自分のv1](../v1/README.md)で22対象の診断・実装・検証・予測CSV作成を完了した。最終採用は追加属性MIA＋公式AIA＋本番専用の非共有163人処理。下記の候補すべてを採用したわけではなく、採否と根拠はv1 READMEに記録した。

2026年9月30日。team10の新しい攻撃系列をv1から検討するための作戦メモ。v88と既存のattack_researchは参照していない。今回実施したのは公開仕様の調査と配布物の集計であり、攻撃予測・提出ZIPの作成や公式採点は行っていない。

最優先は、自チームのAIA問題から確認できた非共有163人をMIAの陰性として利用し、残りの候補について、相手が保存している属性を調べることである。真の希少群、転帰時刻、背景データ由来の行も別に扱う。人数と共有関係による調整はその後に加える。AIAの年齢帯ごとの半数制約は、実配布で確認できていないため厳密に固定しない。

「確認済み」は資料や実ファイルの観察、「導出」は明示した条件からの推論、「候補」は効果を今後検証する手法を指す。改善量や公式得点は未測定。

## 実配布で新たに確認したこと

集計は [audit_public_clues.py](audit_public_clues.py) で再現できる。攻撃用の既存Python環境を使用し、分析前に公式source_manifestの94ファイルすべてのハッシュ一致を確認した。結果は [public_clues_audit.json](../local-output/v1-planning-20260930/public_clues_audit.json)。数値はDecimalで比較し、近似一致や163人に合わせる丸めは使っていない。個人の値や行IDは集計結果に保存していない。

| 確認済みの観察 | 解釈と作戦への反映 |
|---|---|
| 自己challenge326行のうち、公開7属性がB10と完全一致するのは163行。各一致先が一意で、異なるBの163人に対応する | 仕様どおり標的163人の公開属性がB由来なら、全標的が一致集合に含まれ、一致集合の人数も163なので、この集合が標的集合となる。標的はP10由来のため、他22対象のMIAでは陰性として扱える |
| 一致163人は発症16人、真希少13人、希少発症4人 | 公式の標的構成と一致し、上の配布物解釈を補強する。真希少24人のうち13人を非共有として識別できる。残り11人が全員共有者だとは断定しない |
| 一致163人のうち死亡12人 | 非発症147人を一律に10年と扱うと誤る実例。死亡と行政打切りを分ける。これは自チームの標的の値であり、他チームの死亡人数ではない |
| 他22チームのchallengeは、自分のBへの公開7属性完全一致が0件 | 相手の非共有者と外部対照という仕様と整合する。MIA共有者そのものをAIA標的として扱わない |
| 県・性別・floor(age/5)で分けると、0、6、22、27の4コホートで奇数人数の層がある | 「5歳帯の各層で必ず標的と対照が半数」という実装は不適合。公式の年齢帯境界や抽出の詳細が未確認のため、硬い制約にはしない。奇数の原因を断定しない |
| 県・性別だけの各層は全23コホートで偶数。自己10では照合から得た標的と対照が各層で同数 | 対応条件の裏付け。ただし他チームで人数が偶数であることだけでは、その層のラベル内訳を実証したことにはならない |
| 全23コホートのchallengeを横断して、同じ公開7属性の組が複数コホートに現れる例は0 | 今回、challenge間の同一属性再登場を利用する案には観測された材料がない。対照の生成が全体非復元抽出であることの証明ではない |
| 全23件で、Cの13属性が自分のBと完全一致する行は0 | 全列完全一致だけのMIAでは実配布を捉えられない。部分一致、丸め、ノイズ、属性組、時刻などへ進む。個人情報が残っていないことの証明ではない |
| C3の末尾だけが、各列について前1,048行に存在する値のみで構成される。末尾と全13属性が同じ既存行は0 | 補完告知と整合する唯一の候補。列別ドナーによる組合せと整合するが、運営から対象番号や生成方法を直接確認したわけではない。通常扱いと低い重みでの感度比較を行う |
| C3にはA_bgと全13属性が完全一致する行が40件。他22件では0 | 背景由来の可能性が高い行を、相手の個人保持の証拠として過大評価しない。全Cの別方式への変換や無条件な40行削除ではなく、照合・密度計算での重みを比較する |

自己challengeに関しては、PDF p21の「自己challengeを受け取らない」という記述と、9月27日案内・実配布の23件収録に差がある。本メモはハッシュ検証した本戦の実配布に基づく。自己10への攻撃結果は提出対象に含めない。

163人を陰性と扱えることと、公式のMIA得点が改善することは別である。元から低順位なら得点は変わらない。またこの163人は人数構成をそろえた標的抽出であり、陰性全体の無作為標本ではない。この集合だけを使って公式FPRを推定しない。残り886人にも非共有者と対象外7コホートとの共有者が残る。

自己AIAの163人については自Bからtimeが分かるが、対照163人のtimeは分からない。完全な自己AIA得点Rが計算できるわけではない。

## 公開仕様から加える作戦

| 確認した事実と根拠 | 攻撃への候補と判断基準 |
|---|---|
| 公式参照MIAはage、BMI、SBP、TG、HDL、ALT、FPGの7連続列を使う。自Bと相手Cには13属性がある（公式mia.py、common/schema.py） | 性別、県、喫煙、time、onset、deathも調べる。全13属性一律の距離ではなく、検査値のみ、公開属性、転帰を含む属性組など複数の照合を比較する |
| timeは日数を365.25で割った値。発症、死亡、約10年の追跡終了のうち先に起きた観測時刻（公式生成説明、入門notebook、submission_schema.py） | MIAでは発症・死亡の日数と他属性の一致を重視する候補を作る。約10年は多数が同じで識別力が低い。浮動小数や丸めに対する比較方法を固定し、Cが時刻を再生成していれば重みを下げる |
| 自B_selfには真のis_rareがある。公開Mahalanobis検出と真の希少は異なる。AIAではBMIとFPGが非公開（PDF pp6,11,17,19、scoring_io.py） | MIAは真の希少群内の順位を独立に診断する。希少者全員を一律に高くしても希少内順位は改善しない。AIAの推定希少ラベルは確率として扱い、真値として固定しない |
| 希少群はFPGを他検査値との相関を通さずずらすなど、多数派と異なる生成。若年・低BMIの方向づけと2型の混合がある（公式生成説明） | FPGの条件付き残差、属性間の不釣合い、相関を考慮した距離を候補にする。AIAでBMI/FPGを多数派モデルの一点予測で埋めると希少の特徴を消す可能性があるため、複数の可能性を扱う |
| P_iが地域構成の偏りを担い、各Bは同一分布の独立標本ではない（PDF p6） | Cで密度が高い理由を、地域構成と個人保持に分ける。県・性・年齢を条件にした背景比較と無条件比較を両方評価する。地域だけでMIA共有者を高順位にしない |
| U_genは相関・裾、U_rareは希少の分布と発症、U_specはCoxの関連を保存させる（PDF pp14–18） | 匿名化側が維持しようとする属性の順位、裾、組合せを診断する。原尺度、log尺度、順位尺度、相関を考慮した距離を比較する。高有用性だけを個人保持の証拠とはしない |
| A_bgはどのBにも含まれない。Cは合成や背景行の再利用を含み得る（PDF pp2,18） | A_bgに近いCの行と、候補者に固有な一致を区別する。背景から作った部分の局所密度が高くても、そのこと自体を所属証拠にしない |

| AIAは±0.5年で成功し、memberとcontrolの的中率差を使う。死亡はマッチ条件に列挙されていない（PDF pp9,20–22） | 発症、死亡、追跡終了の混合としてtimeを予測する。平均年数ではなく幅1年に入る確率を重視する。ただしmemberだけの成功率や全体誤差ではなく、対照との差も比較する。16人発症だから残り全員10年という予測は使わない |
| 原本Cの数値桁、改行、行順は運営に変更されず配布。例外は補完1行。record_idはコホート内の連番（9月27日案内、submission_schema.py） | 生の数値表記、丸め刻み、列別精度、行順の切替、部分的な加工を診断する。IDそのものをコホート間の同一人物IDとして使わない。書式や順序は補助証拠であり、未知の行対応を決めつけない |
| MIAは相手ごとのROCでありAUCは参考値。全体と希少のmaxを相手ごとに取り平均（PDF pp19,22、attack_score.py） | 最上位の誤検出と希少内の順位を中心に比較する。単調変換だけでは相手内の順位は改善しない。相手横断の配分に使う際は、別方式で得た確信度をそのまま比較せず尺度を調整する |

## v1 の設計順序

1. 公式参照出力を比較用に凍結し、入力、列、乱数、尺度を記録する。v88から手法や成績を引き継がない。
2. 自己challenge由来の非共有163人を再現可能に識別する。予測時の内部マスクとして使い、真の希少群のうち13人を含むことも検証する。個人単位の派生ファイルを不用意に増やさない。
3. 22相手について加工診断を行う。保存列、検査値の丸め、時刻の保存、背景由来、重複、末尾行、分布の偏りを確認する。C3は補完と背景由来を分けて診断する。
4. MIAの候補は、検査値による照合、転帰を含む照合、背景補正した局所密度、希少向け照合を比較する。確信度が強い対応から相手の加工の特徴を学ぶ。
5. 人数枠25〜27人と共有の排他性を使ってMIAを調整する。未割当先を残し、推論の不確実さを0/1へ早期に潰さない。未知の29相手すべてを観測できたことにしない。
6. AIAは公開属性による照合からtime候補の分布を作り、追跡終了と発症・死亡を分ける。MIAで判明した加工の特徴を転用する。本人特有の一致と一般的な予測を分けて評価する。
7. AIAの対応・人数条件は、確定している総数と、実証できた条件から加える。5歳帯による厳密半数の固定、発症なしを10年に固定、対照同士の再利用を仮定する処理は採用しない。
8. 非共有マスク、追加属性、希少専用、背景補正、共有調整、AIA時刻選択、補完行処理を一つずつ比較する。効果を確認してから統合し、公式得点がない段階で優劣を断定しない。

## 評価の限界と資料

自Bの全員対A_bgという簡略比較だけでは、本番の共有25〜27人対残り、自Bの地域構成、AIAの条件付き抽出と未公開対照を再現できない。予備戦の公開正解を利用する場合も、本戦とは独立データであり、同じ分割で調整と評価を繰り返さない。既知陰性163人の誤検出抑制は直接診断できるが、未知の共有者をどれだけ当てたかは別途検証が必要。

公開資料にある抽出条件を超えて、年齢帯の境界、候補不足時の対応、ペアごとの希少一致、行順と共有先の対応、生成乱数やプールIDを仮定しない。これらの推測を使う場合は、一般化を確認した独立の実験として扱う。
