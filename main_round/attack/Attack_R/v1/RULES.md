# R v1の公式ルール対応

確認対象は `main-process-20260912`（[本戦ルール保管先](../../../rulebook/README.md)）と、公式の [main-attack-20260928リリース](https://github.com/pwscup/pwscup2026-kit/releases/tag/main-attack-20260928) です。キットはコミット `a490490e11a0ec460a5df9fdefb17c72ad459c1e` に固定しています。

| 公式節 | このモデルの対応 |
|---|---|
| 4.1 / 4.2 | MIAとAIAをそれぞれ推定。両方式は別々に選択できるため、ユーザー指定のM v2とT v88を組み合わせる。 |
| 5.2 | ZIP直下の3ファイル名、列名、実配布record_id、全対象とchallenge_row_id、値域・有限性を検査。自己対象10を除外。 |
| 5.5 | 配布されたteam10のトークン原本のバイトをZIP内とメモリ上で比較。ローカル検査では運営側の登録状態までは確認しない。 |
| 6.3 | MIA・AIAの公式採点は別成分で、AIAには非公開の補正がある。異なる模擬実験の得点を足して公式得点としない。 |
| 7.4 | 入力は当該競技の自己配布B、B_self、A_bg、公開C、challengeとschema。相手の非公開Bや競技外の人物データは使わない。 |
| 7.5 | AI支援による実装。運営システムへの攻撃や配布データの外部公開は行わない。 |

T v88が出す `time_hat=11` は元モデルの棄権的出力です。公式検証器には上限10の制約はなく、この作業では有限・非負を厳密に検査します。上限10への丸めは行いません。これは的中や得点の保証ではありません。

予備戦コードの一部はT v88の固定済み計算依存として使用しますが、今回の推論で予備戦の参加者データを読み込みません。保存済み学習モデルを再利用し、公式の正解や提出結果による再調整は行いません。

ローカル検証は公式 `validate_submission_zip` と、team10の実配布IDを使う厳密検証を併用します。ZIP内CSVと個別保存CSVのバイト一致、CSV再読込、2回の独立生成一致を確認します。公式提出はこの作業に含めません。
