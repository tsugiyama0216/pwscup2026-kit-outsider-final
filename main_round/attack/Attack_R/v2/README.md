# Attack_R v2

2026-10-07のユーザー依頼に基づくR v1の改良版。R v1のユーザー提供公式結果（OK、攻撃力0.169387840941965）を出発点とし、本番と模擬の分布差に対応する候補を比較する。既存の `v1/`、`v2f/` は保持する。作成時点では本版の公式点は未測定でした。

## 正式結果（2026-10-07受領）

[正式結果の原本](official_results/20261007/)を保存しました。チームID 10、検証OK・採点完了、攻撃力合計 **0.1966605682146923**。R_v1の **0.169387840941965** から約 **0.0272727273** 上昇しました。MIA全体が上昇し、MIA希少・AIA全体・AIA希少は同値です。

[全5指標の比較・照合記録](../README.md)を参照してください。日付は受領・保存日で、採点日ではありません。以下の採用過程と検証JSONは作成時点の模擬評価記録として保持します。

## 採用結果

MIAはT v88の出力を対象内順位へ変換し、厳密に分かる非共有163人を0にする。AIAはT v88を維持する。独立した今回の比較でも、選ばれた成分は既存v2fと同じだった。新しい幾何距離方式や対象間補正が採用方式より優れるとは確認できず、不採用とした。v2fを上回る新アルゴリズムとは主張しない。

調整用2世界の補正込み模擬合計は、R v1が **0.5722437008343182**、R v2が **0.6852157288063462**（差 **+0.112972027972028**）。両世界でMIAが改善し、AIAは同じ。公式0.169387840941965とはデータ・正解・φが異なるため直接比較しない。

選択固定後の確認用2世界でも改善した。全22対象を含め、模擬φを控除した公式形式の集計値は次のとおり。既存v2fはこの表のRv2と同じ予測・得点になる。

| 確認条件 | R v1 | R v2 | 差 |
|---|---:|---:|---:|
| mixed / holdout / 2026100721 | 0.673852474 | 0.762448692 | +0.088596219 |
| stress / holdout / 2026100722 | 0.588793694 | 0.637465023 | +0.048671329 |
| 2世界平均 | **0.631323084** | **0.699956858** | **+0.068633774** |

確認時のMIA平均は0.246683502→0.315317275、AIA平均は両版とも0.384639582。独立生成を除いた追加診断でもMIA差は+0.076331361だったが、主集計からは除外しない。独立生成で正の得点が出ても真の漏洩の証拠とは扱わない。対象・方式ごとの記録は `evidence/development_by_target.csv` と `evidence/confirmation_by_target.csv`。

GitHub保存の追加依頼に対応し、調整終了後・確認開始前に過去のトークン入りZIPを任意にする移植性修正だけを行った。既存ZIPがあれば照合し、旧版CSVと依存ファイルの検査は常に必須。数値モデルと選択は変更せず、変更前の選択・ハッシュを `selection_before_portability.json`、差分を `portability_revision.json` に保存し、ソースを再固定してから確認を開始した。

確認終了後には、再生成の検証記録を新しい出力先へ保存する処理と、完了済みの比較記録を上書きしないガードだけを追加した。数値モデル・採点式・採用成分は不変。`write_safety_revision.json` と変更前ソースの `evidence/*_before_write_guards.py.txt` に記録し、提出生成前に219件の非認証依存を固定した。新しい評価には凍結済み `evaluate.py` の再実行ではなく、共通杉山採点へ `plugin.py` を渡す。

## 比較方法

共通の杉山採点 `main_round/mock_test/sugiyama_v2/` を利用する。MIAとAIAは同じ模擬世界の22対象で計算し、固定公式 `score_attack`、希少層SE補正、対象別φ控除とclip、22対象平均を使用する。φは背景から1,049行の非復元抽出と公式参照攻撃を1,000回行って推定した模擬値。独立生成の対象も除外しない。

`protocol.json` に候補・seed・採用基準を評価前に記録した。調整はdevのmixed/stress各1世界、確認はholdoutのmixed/stress各1世界。各段階44対象。候補を成分ごとに選び、どちらかの世界で0.03超、方式別平均で0.10超悪化する候補は除外する。調整平均の改善が0.005以下なら元成分を保持する。選択とソースハッシュを固定してから確認を始め、確認結果では選び直さない。

## 実装

- MIA候補：R v1のM v2方式、T v88、Tへの対象間補正、T/M混合、7連続属性による近傍密度比とその対象間補正。新しい距離はTG/ALTをlog1p変換し、背景の標準偏差で標準化。性別・県を有限の距離罰則にし、time/onset/deathを使わない。いずれも自己公開情報から厳密に分かる非共有163人を0にする。
- AIA候補：元のT v88、公開5連続属性の最近傍、5/15近傍の±0.5年の時刻窓、背景に対する時刻窓の超過、近さに基づく棄権、元のT出力への限定的補完。全対象で同じ方式・パラメータを使う。公開質問の小さい層で人数の半数を強制しない。
- `model.py` は公開テーブルだけを受け取る。模擬正解・加工方式名・生成seed・ケースの保存パスを渡さない。採点は `evaluate.py` が別に保持する正解を使う。
- 元のM/Tモデルと依存は変更しない。推論時にR v1/v2fの回答も同時生成し、実配布入力では既存CSVとのバイト一致を検査する。

## 保存物と実行

本番22対象を独立2回生成し、両CSVのバイト一致・CSV再読込一致・公式ZIP形式と実配布IDの検査に成功した。MIA1,049行×23列、AIA7,172行×3列。既存R v1/v2fの予測も各回で元ファイルとバイト一致した。Rv2はv2fと同じCSVで、R v1からはMIA19,492セルだけが変わり、AIAは不変。既知非共有163人は全対象0を維持する。

モデル7件と提出4件の計11テストが成功し、20種類の不正提出を拒否した。ZIP直下は両CSVとtoken.txtの3件だけ。トークンは配布原本とメモリ上で照合し、別の平文コピー・内容表示・個別ハッシュ記録は行っていない。R v1/v2fとM/Tの固定ファイル・原本を保持した。

- `selection.json`：調整結果、採用成分、確認前の固定ハッシュ。
- `development.json` / `confirmation.json`：同一条件でのR v1・v2f・v2比較。詳細CSVと生成データはGit除外の `main_round/mock_test/local-output/R-v2/`。
- `submission/F_mia.csv` / `submission/F_aia.csv`：本戦22対象の回答。
- `submission/team10_R_v2_attack.zip`：両CSVと配布原本のtoken.txtだけを格納するローカル提出ZIP。Git除外。
- `verification.json` / `acceptance_checks.json`：2回生成、公式ZIP・実ID検査、悪い提出の拒否、旧版不変の記録。

リポジトリ直下で `./main_round/attack/Attack_R/v2/run.ps1` を使う。既存提出先を上書きしない。再現時は `-OutputDirectory` でv2内の新しい保存先を指定する。杉山採点には `plugin.py` を指定できる。

GitHub版にも `submission/` のCSVを保存するため、取得後の再生成には新しいフォルダーを指定する。本戦環境が未構築なら、先に既存の `main_round/attack/setup.ps1` を実行する。

```powershell
./main_round/attack/prepare_attack_m.ps1
./main_round/attack/Attack_R/v2/run.ps1 -OutputDirectory main_round/attack/Attack_R/v2/reproduced-submission
```

旧R v1/v2fのトークン入りZIPは再現に不要。両版の比較用CSVと固定依存は必須であり、既存ローカルZIPがある場合には作成時ハッシュも照合する。ZIPの新規作成は配布原本のtoken.txtを参照する。

公式結果の5つの集計値から相手別の正解やφは復元できない。既存モデルと模擬生成器・人物分割は過去に使われており、新seedも未知の実人物による評価ではない。模擬で改善しても本番の改善を保証しない。

同日の追加依頼により、モデル・提出CSV・検証記録と必要な非認証依存を既存非公開GitHubのmainへ保存する。`protocol.json` のGitHub未許可という項目は比較開始前の履歴。トークン入りZIPはこのPCのみ、生成した大きな模擬データと通常の中間出力はGit除外を維持する。CodaBenchへの提出は行わない。
