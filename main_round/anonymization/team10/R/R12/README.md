## 何をしているか

例として「ある合成人物のBMIは通常群で下から100番目」という順位を残す。
BMIの分布は256個の代表値で表し、100番目に対応する値を隣り合う代表値の間から直線補間して求める。
同じことをBMI、SBP、TG、HDL、ALT、FPGの6項目で行う。
複数項目の順位の組合せを保持する考え方が、経験コピュラである。

1. **分ける**：R11の合成データを配布schemaの判定で通常993行・希少56行に分ける。
2. **分布を簡潔に表す**：通常群は各検査値の順序統計量を等間隔の256分位点で近似し、順位に応じて補間する。希少群は各列56個すべての値を保持する。
3. **境界を保護する**：補間で希少群へ移ってしまう通常群8行は、6検査値をR11の値に戻す。

年齢・性別・都道府県・喫煙・追跡時間・発症・死亡は、R11の合成値を保持する。
通常群の分布に必要な代表値は `993×6=5,958` 個から `256×6=1,536` 個となる。
これとは別に、順位表、固定列、希少群336値、境界の例外48値を保存するため、モデル全体が1,536パラメータという意味ではない。
境界8行を戻すので、最終結果で全行の順位が完全に保存されるとは限らない。

**簡略化したのはR11を学習した後の生成手順である。** R11をゼロから作るまでの複雑な処理は来歴として残る。
R12は、元Bだけから新たな単純モデルを独立学習したものではない。合成行の順位・属性・転帰の組合せをR11から受け継ぐ、固定行数の決定的な再生成モデルである。
R11そのものの名前変更ではなく、通常群の検査値を補間値へ置き換えている。

## 比較実験

最初に16・32・64・128・256・512分位点の6候補を比較したが、群の境界を越える行が生じ、すべてR11より低得点だった。
[initial_summary.json](initial_summary.json)に失敗した候補も残している。
この結果を受け、境界を越える行のR11値を保持する処理を加えて、同じ6候補を比較した。
256と512が有用性非低下条件を満たしたため、**試した候補の中で最少の256**を採用した。
256が数学的に必要最少という主張ではない。

計12候補・2バッチ。同じ自己採点データで方式と分位点数を選んでおり、独立ホールドアウト評価ではない。
順位の入れ替え、乱数種の探索、採点器の改変は行っていない。
[experiment_summary.json](experiment_summary.json)に採用基準・全内訳・前バッチのハッシュを保存した。

## 再現と検証

既存Python環境で、リポジトリのルートから実行する。

```powershell
./main_round/anonymization/team10/R/R12/run.ps1 -Mode Test
./main_round/anonymization/team10/R/R12/run.ps1 -Mode Verify
```

VerifyはR11からの学習、保存モデルからの生成、CSVの全バイト一致、公式ZIP形式、ZIP内原本一致、ZIPからの再採点を検証する。
Generateは既存成果物を上書きしない。Researchは比較実験を再実行する。

保存モデルだけからの生成は次の4行で行える。R12ディレクトリを作業ディレクトリとし、別名CSVへ出力する。

```python
import json
from pathlib import Path
from model import generate
generate(json.loads(Path('model.json').read_text(encoding='utf-8'))).to_csv('reproduced.csv', index=False, lineterminator='\n')
```

生成に必要なのはPython、NumPy、pandasと保存済みモデルだけ。元B、Cox推定、最適化器は生成時に不要。
学習時は凍結R11とschemaのみを読む。自チームB・B_self・A_bg・utility_refは公式評価と候補選択に使用する。
元Bの行を新たに対応付けてコピーする処理はない。差分プライバシーや匿名性向上の保証はない。

ユーザーの指定どおり提出ZIPを含めて、このPCと既存の非公開GitHubへ保存する。
CodaBenchには送信していない。[ルール対応](RULE_COMPLIANCE.md)を参照。
