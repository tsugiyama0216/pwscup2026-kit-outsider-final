# R3の本戦ルール確認

確認日: 2026-09-17。公式大会ページが指定する本戦加工版`main-process-20260912`と、保存済みルールブック・固定キットを使用する。R2作成時のルール確認に加え、現在の公式大会ページとリリースを再確認した。

| 根拠 | R3の対応 |
|---|---|
| §4 p.8: 自チームのBからCを作る | team10のBと、同じBから作成した保存済みR2のCを使用。他チームの非公開データは使わない。元Bの個別行と合成行を対応付けない。 |
| §5.1 p.10: 同じ行数、識別子除去、具体値 | 1,049行・13列。record_id・is_rareを含めず、欠測なし。公式スキーマで型・値域・イベント排他・行数を確認する。 |
| §5.3–5.4 pp.10–12: 評価に基づく改善・ローカル自己採点 | 6候補のローカル比較を記録。採点コード・入力原本・ルールブックを変更せずハッシュ照合する。 |
| §6.1.2 pp.16–17: Cox係数・信頼区間・解析結論 | 全9係数の差を用いる部分補正。特定の有意性判定だけを書き換える処理ではなく、実際の13列CSVを公式コードで再解析する。 |
| §6.1.4 p.18: 妥当性・新規性 | 年齢・カテゴリ・事象と時刻を保持。U_validの全項目を計算し、元Bと完全一致する行・C内重複行を拒否する。 |
| §5.5 p.12 / 公式キット | ZIP直下にC.csvと配布原本のtoken.txtだけを配置する。トークンの内容をログや文書に出力しない。 |
| §3.2 / §7.4–7.5: 秘密保持・非公開データ・生成AI | 認可された競技用データのみ使用し、外部公開しない。生成AIの利用は規定で認められている。 |

学習に使う統計量はBとR2の合成CSVから求める。B_selfの希少真値、A_bg、utility_refは候補評価で使い、補正関数には渡さない。最終候補の選択にはローカル有用性を使用する。この分離は設計判断であり、Bだけの学習が規則上義務だとは主張しない。

R1・R2の保存済みデータとコードは変更しない。2026-09-17のユーザーの追加依頼により、R3の提出ZIP・CSV・実装・評価記録を既存の非公開GitHubリポジトリへ保存する。対象ZIPだけを.gitignoreの例外とする。CodaBenchへの送信は行わない。

R2の参照MIA=0はその参照攻撃での観測値であり、R3や他の攻撃への安全性を示さない。R3の参照MIA・公式保護指標は未取得。`tpr_rare=null`は未評価値として扱い、ゼロとは解釈しない。R3は差分プライバシーの保証を持たない。
