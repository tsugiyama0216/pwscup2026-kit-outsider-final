# R11 本戦ルール対応

2026-09-19に[公式大会ページ](https://www.iwsec.org/pws/2026/cup26.html)で正本main-process-20260912を確認した。保存済みPDFと固定公式キットのハッシュはR9と同じで、生成・検証時に照合する。

| 根拠 | R11の対応 |
|---|---|
| §4 自チームBからの合成 | 自チームB・凍結R9・配布schemaを入力とする。Bの個別行と合成行との照合や直接コピーを行わない。 |
| §5.1 データ要件 | 1,049行・指定13列の点値。欠損・識別子・完全重複を含まず、Bとの完全一致行も0を要求する。 |
| §5.3–5.4 自己採点 | 未変更の公式キットで候補を比較。各バッチを事前固定し、バッチ間の改善は適応的であること、同じデータで選択したことを明記する。 |
| §6.1.1–6.1.4 有用性 | 全体・希少群の分布とCox解析を補正。採用にはR9より高い最小値Uと全4ファセット非低下を要求する。 |
| §6.1.3 希少群 | 生成ではschemaによる検出区分だけを利用。B_selfの真の希少ラベルは評価・選択だけに使う。各行の検出区分、希少56件、希少発症18件を保持する。 |
| §5.5 提出形式 | ZIP直下にC.csvと配布原本token.txtのみ。公式ZIP検証と元ファイルとのバイト一致を確認する。 |
| §5.6 / §6.2 得点の解釈 | ローカル有用性Uを改善対象とする。公式AUC・参照MIA・匿名性Anonを含む最終総合得点は未確認と明示する。 |
| §7.4–7.5 秘密保持・生成AI | ユーザーが許可した競技データのみを使用。このPCと指定の既存非公開GitHubに保存し、トークンを文書・ログに出力しない。 |

年齢・性別・地域・喫煙・追跡時間・発症・死亡はR9の各行の値を保持する。検査値6項目だけを変更し、値域と希少区分を確認する。行順や乱数種を探して採点を動かす方法は使わない。B_self、A_bg、utility_refは評価・候補選択に使用し、生成器へ渡さない。これらの分離は設計判断であり、公開データ利用を規則が禁止しているという意味ではない。

差分プライバシーや匿名性の保証はない。R9の公式参照MIA=0をR11へ流用しない。CodaBenchへの提出は行わない。
