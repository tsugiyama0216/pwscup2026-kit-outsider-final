# R2の本戦ルール確認

確認日: 2026-09-17。対象は公式ルールブック **main-process-20260912** と、対応する公式キットの固定コミット `3dd71bd3436f2abfdbb64da97e860f22729ea054`。
大会ページに掲載されている現行の本戦加工フェーズ版を確認した。

## R2の設計と対応

| ルール・箇所 | R2での対応 |
|---|---|
| §4 p.8: 自チームのBを加工してCを作る | 本戦team10のB.csvのみをモデルの学習入力にする。予備戦データや他チームの非公開データは使用しない。 |
| §5.1 p.10: 同一行数の完全点値表、record_id削除 | 1,049行・13列のC.csv。欠測、識別子、区間値、集合値を含めず、配布schemaの値域と型を検査する。 |
| §5.3 p.10 / §5.4 pp.11–12: 得点を見ながらの改善とローカル自己採点 | 固定seedの比較実験と公式ローカル採点を記録。公式提出・提出枠の消費は行わない。 |
| §6.1.2 pp.16–17: 無正則化Cox、係数・信頼区間・解析結論の再現 | 原則無正則化の全9共変量モデルをBから推定。合成人物への事象生成を改善する。 |
| §6.1.4 p.18: 打切り整合、関係の過大強調、重複、新規性 | 公式U_validの全項目を計算する。事象排他と行政打切りを検証。完全一致のB行とC内重複を拒否する。 |
| §5.5 p.12 / 公式キットの提出形式 | 提出ZIP直下はC.csvとtoken.txtのみ。トークンは配布原本のバイト列を直接ZIPへ保存し、内容を表示しない。 |
| §3.2 p.8 / §7.4–7.5 pp.23–24: 秘密保持、非公開データ、不正アクセス、生成AI | ローカルの認可された競技用データだけを利用。生成AIによる設計・実装は規定上許可されている。 |

Bだけを学習に使い、B_self.csv・A_bg.csv・utility_ref.json・希少検出参照を評価専用とする区分はR2の設計上の選択であり、ルールにそれと同一の禁止条項があると主張するものではない。

## 再現・取扱い

- 入力6ファイルを既存のSHA-256マニフェストと照合し、本戦キットのコミットと作業ツリー不変を確認する。
- R1の実装と成果物は保存する。R2の学習・生成・検証・比較記録はこのフォルダーにまとめる。
- 試行記録は`local-output/`に保存し、既存成果物は上書きしない。2026-09-17のユーザーの追加依頼により、R2の提出ZIPだけを.gitignoreの例外として既存の非公開GitHubリポジトリへの保存対象とする。
- GitHub保存はユーザーが指定した`main_round/anonymization/team10/R/R2`を対象とする。モデル名と提出ZIP名はR2のまま保持する。こちらからCodaBenchへの送信は行わない。
- ローカル有用性は公式結果ではない。ルール§5.4には、とくにU_rareが環境差で約0.01変わり得る旨の記載がある。
- 完全合成・非重複だけでは匿名性は保証されない。R2は差分プライバシーの保証を持たず、公式の保護指標・攻撃耐性は未評価。
