# R4の本戦ルール確認

2026-09-17確認。公式大会ページが指定する本戦加工版`main-process-20260912`を使用する。R2・R3で確認した保存済み本戦ルールブック、固定キットの内容を引き継ぎ、現在の公式大会ページの版指定も再確認した。

| 根拠 | R4の対応 |
|---|---|
| §4 p.8: 自チームのBからCを作る | team10のBと、同じBから作成した保存済みR3の合成CSVを使用。他チームの非公開データは使わない。 |
| §5.1 p.10: 行数・点値・識別子除去 | 1,049行・13列、record_idとis_rareを含めず欠測なし。公式スキーマで期待行数・型・値域・イベントの排他を確認する。 |
| §5.3–5.4 pp.10–12: 得点による改善とローカル自己採点 | 計22候補と不採用の理由を記録し、公式採点処理を変更せず比較する。 |
| §6.1.2 pp.16–17: Cox解析の再現 | 元Bの統計を用いて検査値の関係を補正し、R3の全9係数と発症リスクを保持する。実際の提出CSVを公式コードで再解析する。 |
| §6.1.4 p.18: 妥当性・新規性 | U_validの全項目を採点する。元Bと完全一致する行・C内重複を拒否し、行政打切りと事象を確認する。 |
| §5.5 p.12 / キット提出仕様 | ZIP直下にC.csvと配布原本token.txtのみを保存。トークンを表示・文書化しない。 |
| §3.2 / §7.4–7.5: 秘密保持・非公開データ・生成AI | 認可された競技用データ内で作業する。生成AIの利用は規定で許可されている。 |

補正関数はBとR3のみを入力とする。B_selfの希少真値、A_bg、utility_refは候補評価に使用し、候補の最終選択にはそのローカル評価値を使う。Bだけを学習に使う区分は設計判断であり、規則がそれを強制すると主張するものではない。

R1〜R3の保存済み成果物を変更しない。2026-09-17のユーザーの追加依頼により、R4一式とトークン入り提出ZIPを既存の非公開GitHubリポジトリへ保存する。対象ZIPだけを.gitignoreの例外とする。CodaBenchへの送信は行わない。

U_rareの約0.01の環境差に関するルール§5.4の注意を踏まえ、今回の0.0023という小さい改善を公式結果として扱わない。R3の参照攻撃MIA=0はR4の匿名性保証ではない。R4の公式攻撃耐性は未評価であり、差分プライバシーの保証もない。
