# R7 本戦ルール対応

2026-09-18。公式大会ページで確認済みのmain-process-20260912版を継続使用する。保存済みルールブック、固定公式キット、入力原本を生成・検証時にハッシュ照合する。

| 根拠 | R7の対応 |
|---|---|
| §4 p.8 自チームBからC | team10のB、同じBから作成したR6、配布schemaの検出基準だけを生成・補正に使用。他チーム非公開データ不使用。 |
| §5.1 p.10 行数・点値・識別子 | 元Bと同じ1,049行、指定13列。record_id・is_rare・欠測を含めない。型・値域・事象排他を公式スキーマで確認。 |
| §5.3–5.4 自己採点と改善 | 各実験段階の候補を実行前に固定し、未変更の公式評価で比較する。低い上限が判明した候補は打ち切り、未評価項目の得点を捏造しない。全実験記録を保存。 |
| §6.1.2 Cox解析 | 元Bの集計Cox係数・標準誤差を目標とする。合成行間で発症・打切りの組を交換し、公式コードで最終CSVを再解析する。元Bの行・個別発症時刻を移植しない。 |
| §6.1.4 妥当性・新規性 | 発症・死亡件数、時刻の周辺分布を保持。交換対象を同じ検出希少区分に限り、その区分の発症件数を保持する。重複・元B完全一致・不自然な関連・背景データへの異常接近を公式評価で確認。 |
| §5.5 提出形式 | ZIP直下にC.csvと原本token.txtの2ファイルのみ。CSVとトークンのバイト一致を確認。トークンをログ・文書に出さない。 |
| §3.2 / §7.4–7.5 秘密保持・生成AI | 認可された競技用データ内で作業し、ユーザー指定の既存非公開GitHubだけに保存する。 |

B_selfの希少真値、A_bg、utility_refは評価と候補選択に使用する。生成器への入力を上記に限るのは設計判断であり、ルールがBのみの学習を強制するという意味ではない。

多数の候補を同じローカル評価で選択したため、独立な汎化評価ではない。§5.4の環境差に関する注意も踏まえ、R7の値はローカル評価として扱う。R6のMIA=0・AUC=0.515234375をR7へ流用せず、公式攻撃耐性や差分プライバシーを保証しない。

R1〜R6の保存済み成果物は変更しない。ユーザーが指定したこのPCと非公開GitHubへ提出ZIPを含めて保存し、CodaBenchへの送信は行わない。
