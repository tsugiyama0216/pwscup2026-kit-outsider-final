# R10 本戦ルール対応

2026-09-19に[公式大会ページ](https://www.iwsec.org/pws/2026/cup26.html)で本戦正本main-process-20260912を再確認した。R9と同じルールブックと公式キットを使用し、実行時にハッシュを検証する。

| 根拠 | 対応 |
|---|---|
| §4 自チームBからの合成 | 自チームB、凍結R9、配布schemaによる補正。他チーム非公開データを使用しない。 |
| §5.1 提出データ | 1,049行・指定13列の点値。欠損、識別子列、完全重複、Bと完全一致する行を認めず、公式検証を実施する。 |
| §5.3–5.4 自己採点 | 事前固定4候補を未変更の公式自己採点で比較。評価と選択に同じデータを使用したことを明記する。 |
| §6.1 有用性 | U>=R9を採用条件とし、最終CSVを再読込して再採点。年齢・性別・地域・喫煙・事象と時刻を各行で固定する。 |
| §6.1.3 希少群 | schema検出区分を保持し、希少ゲート通過を検証。B_selfの真の希少ラベルは評価だけに使う。 |
| §6.2 攻撃評価 | 公式DOMIAS参照実装を改変しない。独自代理集合のAUCと全体TPRを記録し、公式非公開参照集合の結果と区別する。 |
| §5.6、§6.2 総合評価 | 高い攻撃AUCは匿名性改善ではない。有用性の維持を大会最終総合得点の維持と同一視しない。 |
| §7.4–7.5 秘密保持・生成AI | ユーザーが許可した競技データの範囲で作業し、このPCと指定の既存非公開GitHubに保存。トークンをコード・記録へ出力しない。 |

この版の保存対象はCSV・生成器・設定・評価記録。CodaBenchへ送信しない。R1〜R9とM/S系列の既存成果物は変更しない。生成入力にB_selfの希少真値や公開A_bgを渡さず、これらは評価・候補選択に用いる。この入力分離は設計判断であり、公開データ利用を規則が禁止するという意味ではない。

CSV形式の適合と、匿名性が高いことは別である。ユーザーの明示的なAUC上昇指定に従った実験であり、差分プライバシーや公式AUC上昇を保証しない。
