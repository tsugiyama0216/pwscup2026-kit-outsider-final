# R10: R9の有用性を維持した追加補正と代理AUCによる選択

2026-09-19。ユーザー提供R9公式結果を受けて作成。ユーザーは確認質問に対し、匿名化を強める方向ではなく、**攻撃側AUCの数値自体を高くする**ことを指定した。したがって、R10を匿名性の改善モデルとは呼ばない。

## 提出データ

ユーザーの最新の再保存依頼により、削除前コミット19148a6のR10をバイト一致で復元し、[提出ZIP](submission/team10_R10_defense.zip)を追加した。ZIP直下には固定[C.csv](C.csv)と配布原本token.txtだけを格納する。公式形式検証、CSV・tokenの原本一致、ZIPからの再採点は[package_verification.json](package_verification.json)に保存する。再確認は既存Pythonで`package_submission.py`を実行する。CodaBenchへの提出は行っていない。

## 結果

| U_spec | 0.9994082667811186 | 0.9994978237043326 |

| 公式参照攻撃AUC | 0.518515625 | 未評価 |

R9の有用性欄はユーザー提供公式値で、ローカル再採点とも丸め誤差の範囲で一致した。R10は固定公式キットによるローカル値。全4指標がR9以上で、最小値Uは維持した。代理AUCの差は **+0.0001265985382412** と微小であり、独立データでの向上や統計的に有意な差は確認していない。TPRもわずかに上昇しており、匿名性改善を示す結果ではない。

代理AUCは自チームBの全1,049行を陽性、公開A_bgの全5,143行を陰性とし、未変更の公式DOMIAS `overlap_mia` と `score_mia` で計算した。同じA_bgをKDEの背景密度と陰性評価に使う開発用診断で、独立ホールドアウトではない。公式は運営非公開の `B_ref` とpool所属真値を使うため、代理AUCを公式AUC 0.5185と比較したり、公式AUCが0.765になったと解釈したりしてはならない。M配下の共通評価と同じ代理集合だが、ここに示すTPRは全体のみで希少worst-caseではない。

ここで維持を確認した「得点」は有用性U。公式AUC、参照攻撃MIA=0の維持、匿名性Anonを含む大会の最終総合得点は保証できない。公式AUCそのものは攻撃成功度を集約する直接の採点値ではなく、採点には低FPRでのTPR等が使われる。

## 方法

- 凍結R9のC.csvを出発点に、R9の集計制約付き最適化を追加で180反復する。R9の生成器・保存済みCSVは変更しない。
- BMI、SBP、log(TG)、HDL、log(ALT)、FPGの6列を調整し、年齢・性別・地域・喫煙・追跡時間・発症・死亡は各行で固定する。schema検出による希少区分も保存する。
- 自チームBの全体・希少群分位点、順位相関、Cox係数と情報行列を目標にする。移動範囲をR9からB標準偏差0.25個分以内とし、生理的値域も適用する。Bの個別行との対応付けやコピーは行わない。
- 希少分位点重み4/10/20/40の4設定を事前に定めて比較する。他の重みは全体分位点10、相関300、情報行列100、移動量0.02、希少区分10,000。最適化の目的関数そのものはAUCではない。
- UがR9以上、かつ代理AUCがR9より1e-6超上昇する候補を選ぶ。該当したのは重み4の1候補だけだった。実験結果は全4候補を保存した。

R9と同じく差分プライバシーの保証はない。同じBと代理評価を使った候補選択であり、探索後の成績は独立評価ではない。最適化の収束状態はreport.jsonのauditに記録し、反復上限終了と大域最適性を混同しない。
