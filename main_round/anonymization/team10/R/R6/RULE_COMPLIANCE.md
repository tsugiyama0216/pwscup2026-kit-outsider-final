# R6 本戦ルールとの対応

2026-09-18、公式大会ページの指定版main-process-20260912を再確認。既に確認した本戦ルールブックと固定公式キットを継続使用し、ハッシュを生成・検証時に照合する。

| 根拠 | R6の対応 |
|---|---|
| §4 p.8 自チームのBからCを作る | team10のB、同じB由来のR4、配布schemaの外れ値検出基準で補正する。他チーム非公開データは不使用。 |
| §5.1 p.10 行数・点値・識別子除去 | 1,049行・13列。record_idとis_rareを含めず欠測なし。公式スキーマで期待行数・型・値域・事象の排他を検証。 |
| §5.3–5.4 自己採点と改善 | 事前固定12候補を公式の未変更コードで比較。乱数種・行順をスコア探索に用いない。全候補と選択理由を保存。 |
| §6.1.2 Cox解析 | コピュラ補正後の実際のCSVを公式コードで再解析。比較した追加Cox補正は最終モデルで不採用。 |
| §6.1.4 妥当性・新規性 | 行コピーと重複を拒否。行政打切り10年、事象整合、U_validの全項目を検証。 |
| §5.5 提出仕様 | ZIP直下C.csvと原本token.txtのみ。CSV・トークンの原本バイト一致を確認し、トークン内容を表示・文書化しない。 |
| §3.2 / §7.4–7.5 秘密保持・生成AI | 認可された競技データの範囲で作業し、ユーザーが指定した既存非公開GitHubへ保存する。 |

検出群は配布済みschemaの基準で作る。B_selfの希少真値、A_bg、utility_refは評価・候補選択に用いる。学習入力の区分は設計判断であり、規則がBのみの学習を強制するという主張ではない。

本戦§5.4のU_rareの環境変動に関する注意を踏まえ、0.9193はローカル値として報告する。R6の公式採点・公式攻撃耐性を保証せず、R4の参照攻撃結果も引き継がない。

ユーザー指定によりR6の提出ZIPを含めてこのPCと既存非公開GitHubへ保存する。R1〜R5の保存済み成果物は変更せず、CodaBenchへの提出は行わない。
