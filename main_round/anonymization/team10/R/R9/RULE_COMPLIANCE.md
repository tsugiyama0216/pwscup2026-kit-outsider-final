# R9 本戦ルール対応

2026-09-18。公式大会ページで本戦の正本がmain-process-20260912であることを再確認した。生成時と検証時に保存済みルールブック、固定公式キット、配布原本のハッシュを照合する。

| 根拠 | R9の対応 |
|---|---|
| §4 p.8 自チームBからC | team10のB、Bから生成した固定R8、配布schemaを使用。他チーム非公開データ、他作業者のM1/S系列モデルは生成に使わない。 |
| §5.1 p.10 行数・点値・識別子 | 1,049行・指定13列。record_id・is_rare・欠測を含めず、型・値域・事象排他を公式実装で検証する。 |
| §5.3–5.4 自己採点と改善 | 実験段階ごとに候補を先に固定し、未変更の公式自己採点で比較する。段階間は適応的で、同じ評価データを用いた選択であることを明記する。 |
| §6.1.1 一般有用性 | 周辺分布・順位相関・地域件数などBの集計統計を目標とする。地域再配分は縮小した群重心に基づき、Bの個別行への対応を作らない。 |
| §6.1.2 Cox解析 | Bの集計Cox係数・情報行列から効果と標準誤差を補正する。最終CSVを未変更の公式Coxコードで再解析する。 |
| §6.1.3 希少有用性 | 配布schemaで検出したBの希少群の分位点を使用。希少真値ラベルを生成器へ渡さず、R8の検出区分・発症状態を保つ。 |
| §6.1.4 妥当性・新規性 | 発症110・死亡71・打切り868と、各合成行の時刻・発症・死亡の組をR8から保持。元B完全一致行と合成重複行がゼロであること、群関係の不自然な増強や公開背景データへの異常接近がないことを公式指標で確認する。 |
| §5.5 提出形式 | ZIP直下にC.csvと原本token.txtだけを格納。CSVとトークンのバイト一致を照合する。トークンをログ・文書に出さない。 |
| §3.2 / §7.4–7.5 秘密保持・生成AI | ユーザーが許可した競技データで作業し、成果物はこのPCと既存の非公開GitHubへ保存する。 |

Bの行と合成行の最近傍対応は学習目標にしない。分位点・地域件数・縮小群重心・集計解析を使い、固定R8の合成行を補正する。B_selfの真の希少ラベル、A_bg、utility_refは評価と候補選択にのみ使用する。生成入力をこの範囲に限るのは設計判断であり、Bだけの学習が規則上強制されるという主張ではない。

採用条件はローカルU>0.99、かつR8公式値からの全指標非低下。公式採点で同じ値になることは保証しない。参照MIA=0・AUC=0.5330859375はR8の公式結果であり、R9の攻撃耐性は未評価。差分プライバシーの保証はない。

R1〜R8と他作業者の既存モデルを保持する。GitHubに追加されていたM1の更新はfast-forwardで取り込んだ。CodaBenchへの提出は行わない。
