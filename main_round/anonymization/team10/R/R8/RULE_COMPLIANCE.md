# R8 本戦ルール対応

2026-09-18。公式大会ページで確認したmain-process-20260912版に基づく。保存済みルールブック、固定公式キット、入力原本を生成・検証時にハッシュ照合する。

| 根拠 | R8の対応 |
|---|---|
| §4 p.8 自チームBからC | team10のB、同じBから生成した固定R7、配布schemaの検出基準から加工。他チーム非公開データは使用しない。 |
| §5.1 p.10 行数・点値・識別子 | 元Bと同じ1,049行、指定13列。record_id・is_rare・欠測を含めない。型・値域・事象排他を公式コードで検証する。 |
| §5.3–5.4 自己採点と改善 | 実験段階ごとに候補設定を先に固定して、未変更の公式自己採点で比較する。段階間の選択は適応的であり、独立ホールドアウトとは呼ばない。全比較記録を保存する。 |
| §6.1.2 Cox解析 | Bの集計係数・標準誤差を目標に補正し、合成行の事象を交換。Bの個別行・個別発症時刻を移植せず、最終CSVを公式コードで再解析する。 |
| §6.1.3 希少有用性 | 配布schemaで検出したBの希少群の分布・発症率を集計目標とする。B_selfの真の希少ラベルは生成に使わない。 |
| §6.1.4 妥当性・新規性 | 発症110・死亡71・打切り868と時刻・事象の組の分布を保持。検出希少群の発症率のみBの集計率に近づける。完全な元B行のコピー・合成行重複がゼロであることと、公式妥当性指標を確認する。 |
| §5.5 提出形式 | ZIP直下にC.csvと原本token.txtのみ。CSVとトークンのバイト一致を確認し、トークンを文書・ログに出さない。 |
| §3.2 / §7.4–7.5 秘密保持・生成AI | 許可された競技データを用い、提出物はユーザー指定のこのPCと既存非公開GitHubに保存する。 |

B_selfの真の希少ラベル、A_bg、utility_refは評価・候補選択にのみ使用する。この生成入力の限定は設計判断であり、ルールがBだけの学習を強制するという主張ではない。

提出候補はR7の各有用性指標を下げず、最小値Uが1e-9を超えて改善することを条件とする。丸め誤差は改善と数えない。値はローカル評価であり、公式環境での同点を保証しない。R7の参照MIA=0・AUC=0.5175はR8へ流用しない。R8の公式攻撃耐性は未評価で、差分プライバシーの保証もない。

R1〜R7は保持する。CodaBenchへの提出は行わない。
