# S1公式0点の検証（2026-09-17）

**結論：S1は要修正。提出ZIPから有用性U=0を再現し、直接原因を相関スコア0に特定した。** 公式結果とローカル結果の食い違いは見つからなかった。S1の生成コード、C.csv、ZIP、保存済み採点は変更していない。

有用性とローカル提出物の確認は完了。生成側の原因は条件付きroundサンプラーが有力だが、S1の学習済みDPモデルが未保存のため、同じモデルによるround/sample比較は未実施。サーバー非公開入力が必要な参照MIAの実数値再計算も対象外とした。

## 0点に至る計算

9特徴量36組のSpearman相関をBとCで比較する。SciPyで採点器の相関ヘルパーを使わず再計算し、平均絶対差0.489979417825729、90%点0.7436770229146195を得た。公式コードと一致する。

```text
平均側の得点 = clip(1 − 0.489979417825729 / 0.4, 0, 1) = 0
90%点側の得点 = clip(1 − 0.7436770229146195 / 0.8, 0, 1) ≈ 0.070404
相関得点 = min(平均側, 90%点側) = 0
U_gen = min(周辺分布0.940515, 相関0, pMSE0.984902, 時間1, 裾0.998871) = 0
U = min(U_gen, U_spec, U_rare, U_valid) = 0
```

根拠：固定kit `starter/src/pwscup2026/scoring/utility.py` の241–243行、422–426行、1088–1095行。本戦で相関指標が最小値集約に追加されたことは公式リリースノートでも明記されている。

正常対照として、元のBをメモリ上だけでCとして自己採点するとU=0.999999999999999、U_gen/U_rare/U_valid=1となった。これは採点器の動作確認であり、匿名化候補でも提出物でもない。

- ローカルZIPは直下にC.csv、token.txtのみ。ZIP内C.csvはS1/C.csvと完全一致。トークンもteam10配布原本とバイト一致（内容・トークンのハッシュは保存しない）。
- Cは1,049行×13列、公式形式検証エラー0。希少検出66件はゲート8件以上。
- 入力原本6ファイルは既存マニフェストと一致。採点用B_selfから希少ラベルを除くとBに一致。A_bg・schema・utility_ref・本戦設定も一致。
- CのSHA-256：`2e2f03966479e80d11c0bd28465232f857f2b41aed99e3df4055008045a162db`
- ZIPのSHA-256：`ee4029270662d273a6c47fb92e1572ac24fd10d7d13f626f60b6a825c4ef0b5a`

形式・トークン不備の公式処理は全指標0とFailedを返す（`kit/codabench/run.py` 210–232行）。今回の3つの非zero facetを含む結果とは異なる。今回の0が希少ゲート、ZIP破損、DP違反のペナルティによるものという証拠はない。なお、これはDP保証そのものの正式監査ではない。

## 参照攻撃の0は別の意味

`reference_attack_mia=0` は参照攻撃の成功度であり、防御側のprotectionは `1 − reference_attack_mia = 1`。有用性Uは別に計算されるため、攻撃側の0がUを0にしたわけではない（`kit/codabench/scoring_io.py` 194、203–229行）。

`tpr_at_low_fpr=0` は偽陽性率1%での検出率が0だったこと。AUC=0.450546875は診断値で、MIA得点の集約に使用されない。`tpr_rare=null` は希少評価が未算出という意味であり、希少攻撃成功率0ではない。希少maskがない/空、または参照攻撃候補内の希少メンバー陽性が0ならnullになる（`scoring/attack_score.py` 21–68行、`scoring/result.py` 67–87行）。Bの希少24件とは母集団が違うため矛盾しない。

非公開のB_ref、pool_ids_ref、pool_ids_10が手元にないため、参照攻撃の数値そのものは再計算していない。どのnull条件だったかも断定しない。この1本の参照攻撃に対するprotectionは、本番の全攻撃者に対する匿名性の保証ではない。

## 生成側の診断と修正案

S1の共変量には本来ない強い正相関がある。今回の独立計算でも、BMI–HDLはBで−0.0334→Cで+0.7733、TG–HDLは−0.0488→+0.7365、age–HDLは−0.0085→+0.7723となった。

前回の [人工モデル検証](../s1_improvement_20260917/synthesis_audit/toy_sampler_results.json) を再利用した。OpenDP 0.15.1から呼ばれるmbi 1.1.0の条件付き `round` は、同じ親を共有する子変数に同じ行順位由来の乱数層を使い、独立な一様モデルでも子変数間の相関が約0.999になった。同じモデルで `sample` は約−0.06〜+0.05。この実装上の問題は人工モデルで確認済みだが、S1の誤差の全量を帰属できるわけではない。

**提案：S2でまず `synthesis.method=sample` に変更し、学習したDPモデルを保存して同じモデルからの後処理を比較する。** 相関の平均・90%点および4つの有用性を提出ZIPから確認してから提出候補にする。行全体の並べ替えだけでは列間相関は変わらず、修正にならない。本検証では新しいDP生成、S2作成、CodaBench提出、GitHubアップロードは実行していない。
