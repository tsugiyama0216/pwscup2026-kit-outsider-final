## 修正内容

1. `synthesis.method` を `round` から `sample` に変更。生成器は設定検証と実抽出の両方でsampleを必須にし、round・設定漏れ・誤記を拒否する。
2. OpenDPによる測定後、合成前にDPモデルを保存。数値配列とJSONのみを格納し、pickleは使わない。公開キーの順序・型・null枠、モデルのpotential/marginalを保持する。復元はsynthesize/project専用で、標準偏差計算やDP学習の継続には使用しない。
3. 既存ledger・既存成果物を再生成で上書きしない。梱包時に生成コード、保存モジュール、モデル、設定、Cのハッシュを検証する。自己採点は提出ZIPそのものを入力にする。

ライブラリー本体は変更していません。OpenDP 0.15.1 / mbi 1.1.0、ρ=0.1、一変量・固定・適応測定の予算、workload、公開A_bgによる後処理はS1と同じです。設定の差は合成methodとバージョン・来歴だけです。

## 同じモデルによる不具合の確認

S1とS2は別のDP計測なので、その比較だけでは乱数によるモデル差を除けません。そこでS2の保存済みモデルを1つ復元し、同じ公開設定、同じ背景データ、事前固定seed=0でround/sampleを比較しました。Bを再測定せず、追加DP計測は0回です。この対照CSVは診断専用で、提出ZIPには入れていません。

| 同じS2モデルからの抽出 | 有用性U | 相関差の平均 | 相関差の90%点 |

同じ学習済みモデルでも旧処理で0点が再現し、sampleで回復しました。これは今回の修正効果を支持します。上表のsample対照はseedを固定した別の後処理結果であり、提出用S2のU=0.548413とは区別します。点数でseedを選び直したり、Cを差し替えたりしていません。

## 実行方法

このPCの既存AIM環境・採点環境を再利用します。公式キットの既定場所はS1/local-output/official-kitです。`-AimPython`、`-ScorePython`、`-KitRoot`で明示変更できます。

```powershell
# S2フォルダー内から。生成済みのためGenerateは拒否される。
.\run.ps1 -Mode Preflight
.\run.ps1 -Mode PackageExisting
.\run.ps1 -Mode Score

# AIM用Pythonで、公開人工データだけを用いるテストを実行。
python -m unittest discover -s scripts -p 'test_*.py' -v
```

診断用の `scripts/compare_samplers.py` は保存済みモデルと公開A_bg/schemaだけを読みます。`scripts/evaluate_fix.py` は採点環境で実行し、B/B_selfをローカル評価に使用します。比較実験は起動前に `PYTHONHASHSEED=0`、抽出・復号seed=0を設定しました。DPノイズのseedは固定していません。既存の比較CSVは上書きしません。

各候補のρ=0.1・dp_release_count=1は、その候補のDP測定についての記録です。S1とS2は計2回の別計測で、両モデルのDP出力を併せて扱う単純合成ではρ=0.2になります。非DPの自己採点や候補選択を含む開発工程全体が、単一のρ=0.1で保証されるという意味ではありません。
