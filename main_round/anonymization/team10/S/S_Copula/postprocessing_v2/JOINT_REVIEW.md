## 実行して確認した事項

- freeze と manifest の共通内容が一致。コード 7 ファイル、生成スクリプト、
  公開選択 JSON、設定 JSON、親モデル・親 manifest、生成 C・model の
  SHA-256 がすべて記録値と一致した。
- 親モデルと親 manifest の会計が一致し、各親で histogram + Cox の予算が
  親 ε と一致した。全親の histogram 合計は `56/5=11.2`、Cox 合計は
  `14/5=2.8`、合計は **14**。公開人数は 1049、δ は 0。
- 各親の幾何ノイズパラメータが、記録された感度と割当予算に対して
  `q = sensitivity / (sensitivity + epsilon)` を満たした。
- 公開選択結果は 2 コホート × 2 ノイズ試行 × 6 設定の 24 行。
  全設定の平均・最小 utility を再計算し、明記された順位規則を適用すると、
  保存済み設定と同じ `histogram_beta_weight=0`、`radial_strength=0` が選ばれた。
  選択設定の公開代理 utility は平均 **0.6336075097961835**、
  最小 **0.6213743673493561**。
- 保存済みの親 DP モデルだけから、固定設定で `construct()` を再実行した。
  再生成 C の CSV バイト列の SHA-256 が保存済み C と完全一致し、再生成 model
  オブジェクトも保存済み model と完全一致した。ファイルへの再出力はしていない。
- manifest / model / Cox target / histogram 後処理メタデータの外側の会計は
  ε14・追加 0 と整合。optimizer は合成表・保存済み DP 目標・公開パラメータ

## 選択経路と解釈

公開試験コードは A_bg を 1049 行の代理コホートと重複のない公開残部に分け、
代理コホートだけにノイズを加えて各設定を比較する。採用する設定は公開試験の
全体 utility で決まり、本番生成スクリプトには私的評価関数や私的入力パスがない。
本番の最適化途中の選択基準も、合成表と DP 目標の差だけである。
この確認範囲では、私的スコアを候補選択に流用する経路は見つからなかった。

以下は今回の生成を阻害する問題ではないが、説明と再利用の際に注意する。

- `histogram_model.privacy` は互換性のため親のクエリ情報を保持し、内部に
  ε8 の値が残る。**joint14 全体を ε8 または ε10 と説明してはならない。**
  外側の ε14 および `histogram_postprocessing.parent_epsilon_exact` が合算会計。
- `pipeline.construct()` の外側の ε14 表示は今回の三つの親を前提とする。
  別の親セットに汎用利用するときには、その表示をそのまま信頼しないこと。
  今回の CLI は ε1, 3, 10 と親ハッシュを明示的に検証している。
- 公開試験の 2 コホート・各 2 ノイズ試行は限定的な選択根拠であり、実際の
  private utility や utility 0.9 を保証しない。公開試験自身にもこの限界が記録されている。
- 後日作る実 B に基づく診断スコアや診断レポートは、この DP 生成物の会計には
  含まれない。そのような別資料がある場合は、ε14 の保証対象と区別して扱う。

今回のレビューは保存済み成果物と現在の実行経路の確認であり、過去の全操作や
人間の判断履歴についての監査を代替するものではない。
