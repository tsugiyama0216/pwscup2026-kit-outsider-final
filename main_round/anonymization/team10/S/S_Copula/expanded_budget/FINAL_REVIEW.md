## 保存条件と CSV 表現

runner が読み込んだ base C と、最終 C を `float_precision='round_trip'` で
読み戻した表を比較し、次を **完全一致** で確認した。

- outcome 以外の全予測変数行。
- 公開検出器で定義した各 rare 層内の `(time, onset, death)` の多重集合。
- 1049 行、指定列、欠損なし。

通常の pandas パーサーで再読込した浮動小数点値が、ファイル間でビット単位に
一致するという意味ではない。両 CSV を既定パーサーで読むと、75 数値セルに
最大 `2.842170943040401e-14` の再変換差が生じた。round-trip 読込みでは上記の
完全一致を確認でき、アルゴリズムが予測変数を書き換えたものではない。
固定済み C は変更・再生成していない。

## 保証範囲

会計は **累積 ε414** であり、追加分の ε400 だけを全体の予算として表示しない。
数学的な DP 保証の対象は保存済み target と C、および公開情報・DP 出力からなる
後処理結果である。実 B に基づく診断値や入力ハッシュは含めない。

運用台帳の正確な予約・完了時刻は測定実行時間の情報を含み得るため、内部管理に
保持し、DP 配布物へ測定時間情報として公開しない。ここでのハッシュ確認は、
内部記録の整合を確認するためのものである。公開用には会計・固定識別子と
必要なハッシュを利用し、運用時刻や私的診断を分離する。

本監査は保存記録・現在のコード・DP 生成物の確認である。固定台帳の外で行われた
未記録操作を検出できる集中監査システムではない。実 B/B_self/utility_ref の
行データや R 出力は読まず、新しい測定・私的再評価も実行していない。
