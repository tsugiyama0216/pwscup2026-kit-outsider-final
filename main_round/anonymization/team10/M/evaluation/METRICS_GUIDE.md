# 比較表の指標・攻撃手法・解釈

この文書は [MODEL_COMPARISON.md](MODEL_COMPARISON.md) の各列が何を測り、どのように計算され、結果から何を言えるかを説明します。個別モデルの数値と原因仮説は `results/<model>/DETAILS.md`、ルールブックとの対応は [RULEBOOK_BASIS.md](RULEBOOK_BASIS.md) に保存します。

## 評価の目的と対象

目的は、有用性だけをBへ近づけた結果、攻撃者がB由来の行と背景行を見分けやすくなっていないかを、全モデルで同じ条件により早期発見することです。公式の他チーム攻撃や本番challengeは手元にないため、次の代理集合を使います。

- member・AIA標的: `B_self.csv`の1,049行から`is_rare`を除いたデータ
- nonmember・AIA対照・背景参照: 公開`A_bg.csv`の5,143行
- 公開データC: 各モデルの1,049行×13列
- 希少判定: 配布`schema.json`の7連続変数に対するマハラノビス距離と公開閾値

公式候補集合は各チーム25～27 member程度を含む別構成です。この違いにより、ここでの値はモデル間の開発比較には使えますが、公式protection、Anon、順位の予測には使えません。

## 比較表の列

### U

公式本戦キットで各モデル作成時に得たローカル有用性です。一般分布、解析再現、希少群、妥当性の4観点の最小値です。

```text
U = min(U_gen, U_spec, U_rare, U_valid)
```

値が大きいほど、Bの統計的性質や利用目的を再現しています。一方、Bへの一致を強める処理は、BとA_bgの密度差まで再現してMIAを強める可能性があります。したがってU単独では提出候補を決めません。

### MIA β

MIAは「候補行がCの学習元Bに属していたか」を推定する攻撃です。比較表では、2種類のMIAのうち大きい偶然補正後リスクを表示します。

1. 全候補で確信度順位を作り、FPR=0.01におけるTPRを線形補間する。
2. 公開希少判定に該当する候補だけでも同じTPRを計算する。
3. 全体と希少側の大きい方を`beta_raw`とする。
4. membershipと希少フラグの組を保ったまま20,000回並べ替え、偶然分布の95%点`beta_chance`を求める。
5. 次の式で偶然水準を控除する。

```text
beta = max(beta_raw - beta_chance + 0.01, 0.01)
```

最小値0.01はFPR=0.01の偶然相当です。βが大きいほど、誤検出を1%に抑えた厳しい条件でもmemberを上位へ集められたことを意味します。

### 運営DOMIAS KDE

運営参照MIAは、`age, BMI, SBP, TG, HDL, ALT, FPG`の7連続変数をA_bgの平均・標準偏差で標準化し、CとA_bgへガウシアンKDEを当てます。候補xの確信度は次の密度比の単調変換です。

```text
ratio(x) = p_C(x) / p_A_bg(x)
confidence(x) = ratio(x) / (1 + ratio(x))
```

Cで高密度、A_bgで低密度の行ほどmemberらしいと判断されます。完全一致行がなくても、B特有の連続分布・相関・裾の形をCが強く再現すると攻撃が成立します。

### 予備戦由来の多視点MIA

予備戦v4/v9の発想を本戦データへ移したストレステストです。性別×都道府県、性別、全体の順にフォールバックしながら、Cへの最近傍距離を次の4視点で測ります。

- QI: age, SBP, TG, HDL, ALT
- 安定視点: age, SBP, HDL
- 臨床視点: BMI, SBP, TG, HDL, ALT, FPG
- 転帰込み視点: 上記連続値とtime, smoking, onset, death

A_bgの中央値とIQRでロバスト標準化し、対照距離の経験分布から下側p値を作ります。4視点の上位証拠、中央値、同じC行へ結び付く整合性を融合して順位化します。現在は全モデルでβ=0.01でした。これはこの具体的攻撃で追加信号を検出できなかったという意味で、MIA耐性の証明ではありません。

### MIA正規化値を主順位に使わない理由

ルールブックのK=12正規化は次です。

```text
a_MIA = clip((beta / 0.01 - 1) / (12 - 1), 0, 1)
```

代理集合は公式よりmember比率・件数が大きく、S1以外では1へ飽和しました。飽和後はモデル差が消えるため、追跡値としてJSONへ残し、開発順位には飽和前のβを使います。

### AIA R（φ前）

AIAは、公開Cから候補行の秘匿属性`time`を推定する攻撃です。予測が真値の±0.5年なら成功とし、memberの正解率`p_m`が対照の正解率`p_c`をどれだけ上回るかを測ります。

```text
R = clip((p_m - p_c) / (1 - p_c), 0, 1)
```

希少側にも同じ計算を行い、z=1.64の標準誤差デッドゾーンを適用して全体との悪い方を使います。公式ではさらにteam10固有の`phi_i`を控除しますが、値が手元にないため比較表は控除前です。

### 運営QI最近傍AIA

性別×都道府県ブロック内で、`age, SBP, TG, HDL, ALT`をA_bgの標準偏差で尺度調整し、per-feature RMS距離が最小のC行を探します。その行の`time`を予測値とします。ブロックに行がなければ性別、さらに全体へフォールバックします。

### 予備戦由来の多視点AIA

QI、安定、臨床の3視点それぞれでブロック内最近傍C行の`time`を取得し、3予測の中央値を使います。1つの距離定義に依存しない照合攻撃です。10年固定予測もsanity baselineとして記録しますが、最大リスクには含めません。

### 診断用耐性

ローカル攻撃の悪い方を取り、1から引きます。

```text
diagnostic_attack_risk = max(MIA beta, AIA R before phi)
diagnostic_resistance = 1 - diagnostic_attack_risk
```

大きいほど良い指標です。公式Anonの形を参考にしていますが、MIAは公式K正規化前、AIAはφ控除前なので公式Anonではありません。

### floor

```text
screening_floor = min(U, diagnostic_resistance)
```

公式順位が`min(U, Anon)`を使うことに対応した一次選別値です。有用性と耐性のどちらか一方だけが高いモデルを上位にしません。現在の主順位はこの値の降順です。

### balance

```text
balance = 2 * U * diagnostic_resistance / (U + diagnostic_resistance)
```

Uと耐性の調和平均です。floorが同じ場合や、改善の滑らかさを見る補助指標です。低い側を強く反映しますが、minそのものではないため、提出候補の主順位には使いません。

### 耐性余裕 R-U

```text
resistance_margin = diagnostic_resistance - U
```

負なら耐性がボトルネック、正なら有用性がボトルネックです。絶対値が大きいほど両者の不均衡が大きく、次に何を改善すべきかが分かります。

### 判定

開発用の信号強度による区分です。公式の合否基準ではありません。

- `utility-reject`: U < 0.5
- `low-local-signal`: 最大攻撃リスク ≤ 0.05
- `watch`: 0.05 < 最大攻撃リスク ≤ 0.15
- `high-local-signal`: 最大攻撃リスク > 0.15

### 特徴・メモ

各モデルの主要な生成・補正手法と、比較から直接観測できる特徴を短く記載します。原因を断定する列ではありません。原因仮説と反証方法は各`DETAILS.md`に分けています。

## 補助診断

### 希少側MIAギャップ

```text
rare_gap = max(TPR_rare - TPR_all, 0)
```

全体より希少側でどれだけ攻撃が強くなるかを示します。値が大きければ、裾の分布、希少群内相関、希少群の集計値へBを強く合わせた処理を優先して調べます。

### 完全一致と重複

- B完全一致: CとBで13列すべて一致する行数
- A_bg完全一致: Cと公開背景で13列すべて一致する行数
- C内重複: C内部の完全重複行数

これは直接コピーや粗い複製を検出します。0でも密度・相関・近傍構造によるMIAは成立するため、十分条件ではありません。

## 現在の結果から言えること

1. S1以外はDOMIAS MIAがAIAを上回り、提出判断の主な制約です。
2. M1は非S1モデル中で最小のMIA βを持ち、floor首位です。公開A_bgの依存構造を使ったことが、B固有密度への接近を抑えた可能性があります。
3. R5は後期R系列よりUが低い一方、R系列で最良のfloorです。CART葉内サンプリングによる局所平滑化が、希少密度の再現を弱めた可能性があります。
4. R6とR9は希少側MIAが最大級です。希少群コピュラや集計制約によりBの希少連続分布へ強く近づけたことが原因候補です。
5. R8はR6・R7よりMIAが改善しましたが、依然として耐性がボトルネックです。
6. R9はUが最高でもfloorはR6と同じです。U最適化と耐性が同じ方向へ動くとは限りません。
7. 全モデルでB完全一致とC内重複は0です。観測されたMIAは単純コピーではなく、7連続変数の密度形状、とくに希少側の再現から生じている可能性が高いです。

これらはモデル間差分と攻撃仕様から得た仮説です。原因を確定するには、希少補正、周辺分布補正、相関補正、Cox補正を1つずつ外したアブレーションが必要です。

## 判断手順

1. floorで提出候補を一次選別する。
2. 耐性余裕が負なら、Uをさらに上げる前にMIA・AIAを下げる。
3. MIAが支配する場合は、全体TPRと希少TPRを分け、希少ギャップが大きければ希少補正を優先して弱める。
4. AIAが支配する場合は、QIとtimeの近傍対応、同一ブロック内の局所的な転帰割当てを調べる。
5. 完全一致が0でも安全とは判断しない。密度比と近傍攻撃の両方を確認する。
6. 公式challengeまたはteam10のφが入手できたら、代理順位を再較正する。

## 解釈上の限界

- B全行をmemberにした代理集合は公式候補集合と構成が異なります。
- 同じBを使ったローカル有用性と攻撃診断であり、独立ホールドアウトではありません。
- team10のAIA φを控除していません。
- 運営DOMIASと現在の多視点攻撃以外の攻撃には未対応です。
- floor、balance、耐性余裕、リスク帯は開発用です。公式得点ではありません。
