## 本戦ルールとの対応

固定版公式キットcommit `3dd71bd3436f2abfdbb64da97e860f22729ea054` のDOMIAS参照実装をそのまま使用。[同梱公式ルールブック](../../../../../../../official-kit/rulebook/PWS_Cup2026_ルールブック_main-process-20260912.pdf)の§3.1・§4.1・§6.2.1を参照した。A_bgで標準化した年齢・BMI・SBP・TG・HDL・ALT・FPGの7列でKDE密度比を求めた。帯域幅などの攻撃パラメータ探索は行っていない。

1. 各疑似攻撃者は1,049人、member26人、候補希少24人。memberの希少は0〜2人。memberはB_selfから、nonmemberはA_bgから作る。
2. 実際の共有ブロックが互いに重ならない点に合わせ、20攻撃者のmember合計520人は重複なし。ただし本当の共有ブロックは非公開のため、その割当自体は代理抽出である。
3. 各攻撃者でFPR=0.01のTPRを全体・希少候補それぞれで取り、大きい方を選ぶ。希少memberが0なら全体のみ。ROCの同値をまとめて線形補間する公式関数を使用。
4. その20攻撃者の値を平均してβ_rawを求める。全候補を一つに結合したTPRや、攻撃者の最大値は使わない。
5. memberラベルと希少フラグを対のまま、攻撃者ごとに独立に置換し、同じ集計を20,000回行う。その平均値分布の95%点をchance95とする。攻撃者別95%点の平均ではない。
6. β=max(β_raw−chance95+0.01,0.01)、a_MIA=clip((β/0.01−1)/11,0,1)。K=12は固定キットの設定と一致。

置換seedは全攻撃者の確信度・正解・希少フラグのSHA256から機械的に決定する。本実装のシリアライズ規約を保存しているが、事務局サーバーのバイト列規約まで同一とは確認できていない。

## 残る代理評価の制約

- 他チームのB_j、真の共有ブロック、未公開nonmember、公式AIAチャレンジは手元にない。実際の25〜27人という共有人数は26人で近似し、他県コホートの分布の偏りは再現していない。
- Bの希少ラベルはB_selfの真値を使う。A_bgの真の希少ラベルは未配布なので、公開検出器の代理ラベルから希少候補数を24へ揃える。この置き換えは希少側TPRに影響し得る。
- nonmemberとしてA_bgを使い、DOMIASの背景KDEにも同じA_bgを使う。実際の非公開nonmemberとは異なり、背景データへの適合や生成器での公開データ利用による偏りがある。数値の絶対値を公式成績へ外挿しない。
- AIAはB全行を標的、A_bgを対照とする既存の代理方式で、運営QI最近傍と多視点リンクの最大値。φ_iは未入手なので控除していない。公式の標的・対照の構成ではない。
- 共有画像は [原画像](inputs/collaborator_table.png) と [表示値の転記](inputs/collaborator_table_rounded.csv) に保存した。元の疑似集合と攻撃コードがないため、画像の数値との直接照合は行えない。R13の行も本評価には含めていない。
- 「予備戦の攻撃一般が弱い」とまでは検証していない。ここで確認したのは、本戦式集計のDOMIASに対する各固定CSVの挙動である。

## DP出力と採点の区別

ε15はヒストグラム3＋Cox補正12を事前固定し、1回の計測で作成。[保存先](../../../S/S_DPCopula_ep15/README.md)と [設計](../../../S/S_Copula/epsilon15/PRIVACY_DESIGN_15.md) を参照。ε20の過去モデルや評価値を新しいモデルの数値入力にしていない。両モデルの採点・攻撃結果を見て再生成していない。

ε15単独の機構予算は15、ε20と合わせた基本合成上限は35。過去の削除済みε400を含むDPCopula計測履歴は449。評価・比較・内部診断は非DPなので、資料全体や評価によるモデル選択までDP保証を主張しない。εが有限であることと、ある攻撃に対して高いAnon proxyが出ることは別の性質である。
